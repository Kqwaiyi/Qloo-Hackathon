# 10: First Styling: Outfits inspired by ranked Style Icons

**What to build:** After an accepted photo, the Consultation's first Styling runs in the background as a Vercel Workflow. Qloo ranks Style Icons popular with people of the user's age group, Style Preference and Country, in tune with the Photo Style, and the Consultation shows up to two Outfit cards, "Outfit N · Inspired by <Style Icon>". The cards have no Pieces yet: tickets 11 and 14 fill them. This ticket builds the Styling machinery every later kind of Styling reuses, including one shared check that runs before any Styling starts.

**Blocked by:** [06 Upload a photo to start a Consultation](06-upload-photo-start-consultation.md), [09 Qloo client with a 30-day cache](09-qloo-client-cache.md)

**Status:** ready-for-agent

**Spec:** [spec.md](../spec.md) sections "Stylings", "Outfit assembly (pure module)" (Inputs, Age groups, Style Icons, Config, denylist seeds), "Server operations" (Read: the Styling status), "Data model" (Stylings, Style Icons, Outfits) and "Testing Decisions" (Seam 1 inline runner; Seam 2; the Qloo privacy commitment; live checks). - [x] Starting a Consultation now also starts its first Styling. Every operation that starts a Styling goes through one shared start check, so the region, lock and limit tickets each add their check in one place.
- [x] Stylings run as one "build Outfits" Vercel Workflow. Tests run the same step functions in order through an inline runner; the Workflow function is a thin shell over those steps and isn't itself under test.
- [x] Each Qloo call is its own Workflow step with its own retries, backing off on "too many requests". Each step saves its output as it finishes, so a retried step resumes and nothing relies on Workflow's run data (kept 1 day on Hobby). Every step checks that its Styling is still running before it saves.
- [x] A Styling records its Consultation and user, kind, target Budget Tier and Photo Style, status (running, succeeded or failed), stage and when the stage last moved, Outfits wanted and Outfits made, failure reason, Workflow run ID, and start and finish times.
- [x] The Outfit assembly module is pure, with no framework or I/O code. It works out the age group from the birth year and month using the spec's table (18+ only) and builds the Style Icon query: `filter.type=urn:entity:person`; `filter.tags` = model, fashion_model, singer, rapper, actor, athlete, influencer; `filter.gender` and `signal.demographics.gender` from the line; `signal.demographics.age`; `signal.location.query=<Country>`; `signal.interests.tags` = the Photo Style's `personal_style` tags; `filter.popularity.min=0.995`; `take=50`; and `filter.exclude.tags` for the politician, stand_up_comedian and astronomer occupations plus the `genre:person` comedian, academic, journalist and youtuber tags.
- [x] A menswear or womenswear user gets one person call. A no-preference user gets two, one womenswear and one menswear, interleaved W1, M1, W2, M2…. Each Style Icon keeps its line: for a no-preference user, the list it came from.
- [x] The module drops anyone with a death date and anyone on the Style Icon denylist, and keeps Qloo's affinity order. The denylist lives in config, matches by Qloo entity ID with the name kept for readability, and is seeded with the spec's names.
- [x] Queries use the Style Preference, Country and age group stored on the Consultation.
- [x] Each Consultation's ranked Style Icons are stored with the Styling that picked them, their position, Qloo entity ID, name, line and status (unused, used or skipped).
- [x] The Styling builds up to 2 Outfits, one per top unused Style Icon. Each Outfit stores its Consultation, the Styling that made it, its position, its Style Icon and whether it's current.
- [x] When the Styling finishes, its Outfits switch in at once and the Consultation is ready. A Styling that made no Outfit has failed: nothing switches, its reason is recorded as "nothing could be built" or "something broke", and the Consultation shows "No Outfits".
- [x] While the Styling runs, the Consultation shows "Styling…" and the page polls the Styling status route about once a second. The Outfits appear all at once when it finishes. The full checklist comes in ticket 13.
- [x] The results page shows each Outfit card as "Outfit N · Inspired by <Style Icon>". Style Icons are shown by name, never with Qloo's image.
- [x] Local development uses real Qloo through the cache.
- [x] Pure tests cover the Style Icon query for each age group and Style Preference (including the no-preference interleave and per-line gender signal) and for the Country, plus the death-date and denylist filters.
- [x] A server-operation test runs a new Consultation through the inline runner to two Outfits and asserts that the recorded Qloo requests contain no user identifiers.
- [x] An opt-in live check, never run in CI, makes one read-only Qloo tag call confirming that all 11 Photo Style words are real `personal_style` tags.

## Comments

Implemented. Decisions made along the way that later tickets should know:

- **The Workflow.** `src/workflows/build-outfits.ts` is the "build Outfits" Vercel Workflow (`workflow@5.2.2`, switched on by `withWorkflow` in `next.config.ts`). Its function hands its `"use step"` wrappers to `buildOutfits` (`src/server/stylings/build-outfits.ts`), which only orders the steps. Tests hand the same function `stylingSteps(ctx)` through `InlineStylingRunner`.
  - Adding a step touches three places: the `BuildOutfitsSteps` interface, its body in `stylingSteps` (`steps.ts`), and one wrapper in the Workflow file.
  - The Workflow sandbox can't load Node.js code, so each wrapper imports `@/server/stylings/workflow-steps` only when it runs. That module runs the step on `getServices()` and tells the Workflow what to retry: `StylingNotRunningError` and Qloo 4xx are fatal, Qloo's 429 waits for `Retry-After` or 2^attempt seconds, and anything else gets the default retries. The Qloo step retries `QLOO_STEP_MAX_RETRIES` (5) times.
  - Local development uses Workflow's Local World, which keeps runs in `.workflow-data` (`npx workflow web` shows them).
- **The steps:** `styleIconLines`, one `fetchStyleIcons` per line in parallel, `saveStyleIcons`, `makeOutfits`, `finish`. Every step that saves locks the Styling row (`FOR UPDATE`) and saves only while it is running. A retried save that already went through does nothing. The person calls' output is kept by the Qloo cache, and their people pass to `saveStyleIcons` as step arguments within the run (Style Icons in run data, as the Privacy Policy lists). A Try again from Style Icons (ticket 29) refetches through the cache.
- **Finishing** (`finishStyling` in `steps.ts`) switches the Styling's Outfits in (`current = true`) and makes the Consultation `ready`. With none, the Styling fails as `nothing_built` or `something_broke`, and the Consultation stays `ready` only if it still shows current Outfits, otherwise `no_outfits`. It does nothing to a Styling that isn't running, so ticket 30's stuck check can call it. Usage records (22), Previews (12) and re-stylings replacing the current Outfits (27, 28) slot in here.
- **Starting.** `checkStylingStart` (`src/server/stylings/start.ts`) is the shared start check. It is empty for now (`StylingStartRefusal = { refusal: never }`) for the region gate (24), the locks (30) and the limits (22, 23) to fill.
  - `startConsultation` runs it right after sign-in, before the file and the photo check. The spec's order puts consent between the region and the lock, so ticket 25 should settle where consent goes against it.
  - `createStyling` runs inside the caller's transaction, and `launchStyling` after the commit. A run that can't start finishes its Styling as broken.
  - Every Styling starts at stage `style_icons`, and `outfitsWanted` is `OUTFITS_PER_STYLING` (2) until ticket 22 limits it.
- **Data.** New tables `styling`, `style_icon` and `outfit`, and `consultation.state` (`styling`, `ready`, `no_outfits`). Migration 0003 backfills existing Consultations as `no_outfits`. The enums already hold the other kinds and the `brands` and `previews` stages, unused so far. There are no lock constraints yet (ticket 30). The line enum is `outfit_line`: `line` is a built-in Postgres type, and a column typed `"line"` silently gets that instead.
- **Outfit assembly.** `src/server/outfit-assembly/style-icons.ts` has `styleIconLines`, `styleIconQuery`, `rankStyleIcons` and `photoStyleTag`, and `ageGroupAt` moved there from `src/server/consultations/`. The Qloo client's `people()` adds `filter.type=urn:entity:person`. Ranking sorts each line by `query.affinity`, stably and with anyone lacking one last, which changes nothing when Qloo already sends affinity order, as it does with the Photo Style signal. It then interleaves the lines and keeps someone found in both once.
- **The denylist** (`src/config/denylists.ts`) holds the spec's 10 names, with IDs looked up through read-only `/search` calls on 2026-10-16. Liam Payne is Qloo's "Liam Pane" (`8D14B185…`, no date of death). For the team to decide, not added:
  - research candidates Mia Khalifa and Sunny Leone (adult-film backgrounds), Melania Trump (political role) and Kanye West (hate-speech controversy);
  - Zach King, a YouTuber the `genre:person:youtuber` exclusion misses, who was the menswear top pick in the first live run (no-preference, United Kingdom, 30–34, casual).
- **Status and page.** `GET /api/consultations/[id]/styling` returns `readStylingStatus` (`src/server/operations/stylings.ts`): `{ state, stage }`, or 404 for anyone else's Consultation. `StylingProgress` polls it about once a second and refreshes the page once the state leaves `styling` (or on a 404). Ticket 13's checklist replaces the "Styling…" panel, and ticket 29's messages replace "No Outfits".
- **The live check** is `npm run check:photo-style-tags`. It passed on 2026-10-16 for all 11 words. It calls Qloo directly, skipping the cache.
- **Tests.** `harness.qloo` is a `FakeQlooTransport` behind the real `QlooClient` and its cache, and `harness.stylings` is the `InlineStylingRunner`: started Stylings wait for `runPending()`. Empty `qloo_cache` between tests that assert on requests. `src/server/operations/stylings.test.ts` covers the first Styling end to end, the Qloo privacy commitment, the failures and late saves.
- **E2E.** "Get my Outfits" now starts a Styling, so `photo-check.spec.ts` makes one live Qloo call per run. Its navigation to the Consultation got a 15 s timeout, since a cold dev server compiles the page while the Styling starts.
- **For the glossary:** "line" (an Outfit's menswear or womenswear) isn't in `GLOSSARY.md` yet.
- **Live calls used:** about 20 read-only calls on 2026-10-16 (the entity searches, the tag checks, a local dev run and the e2e runs). About 9,680 were left.
